# device_history: архив / партиции (W4-06)

**Статус:** оценка; код партиций в W4 не вводим.

## Когда давит

Большой `device_history` замедляет карточку устройства и бэкапы БД.

## Варианты (additive)

1. Job: перенос строк старше N дней в `device_history_archive` (та же схема).
2. PostgreSQL partitioning by range on `created_at` (требует rewrite PK — осторожно).
3. Урезать выборки в UI (уже есть limit на списках).

## Рекомендация

Пока объём не измерен на стенде — оставить as-is; при росте > нескольких млн строк начать с archive-таблицы + nightly job, без ломки текущих FK.
