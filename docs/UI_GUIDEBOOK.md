# Гайдбук интерфейса bAWH

> Канонический UI/UX-документ для v2.1.  
> Цель: современный, спокойный, гибкий интерфейс администратора сети — одинаково читаемый на ПК и телефоне.  
> Стек: Flask SSR + Jinja2 + Bootstrap 5 (vendor) + `app/static/css/app.css`.  
> Архитектура и маршруты — в [`ARCHITECTURE.md`](ARCHITECTURE.md).

---

## 1. Принципы продукта

bAWH — **инструмент оператора**, не витрина. Интерфейс должен помогать быстро находить устройство, понять статус и выполнить действие — без декоративного шума.

| Принцип | Смысл на практике |
| --- | --- |
| **Спокойствие** | Бирюзовый акцент #0f766e, светлый фон, мягкие тени. Без неона, glow, «дашборд-каруселей». |
| **Одна работа на экран** | Заголовок + короткий subtitle + основной блок. Вторичное — в сайдбаре, вкладках или «Настройках». |
| **Плотность с воздухом** | Оператору нужно много данных, но не «стена кнопок». Группы действий с подписью. |
| **Вход важнее меню** | Вошедший видит все пункты. Анонимный запрос по-прежнему останавливает серверная проверка. |
| **Mobile-first для навигации** | Topbar → collapse; settings sidebar → сетка чипов 2×N (≤900px); карты → одна колонка карточек. |
| **Сущность узнаваема** | Устройство = оранжевый `entity-device`, УЗ = синий `entity-account`. Не смешивать. |
| **Состояние видно сразу** | Online / offline / unknown — цвет левой кромки + badge + точка. Цвет не единственный сигнал. |

**Анти-паттерны:** дублировать одну и ту же кнопку в трёх меню; смешивать «отчёт» и «настройки отчёта» в одном потоке; класть CLI-справку в первый экран; использовать raw Bootstrap-карточки без токенов bAWH.

## 2. Информационная архитектура

### 2.1. Основная навигация (topbar)

Ровно **3** пункта. Порядок фиксирован. Не добавлять пункты без ревью IA.

| Пункт | Кому | Назначение |
| --- | --- | --- |
| **Карта сети** | вошедший | Главный рабочий стол: сектора, устройства, поиск, bulk |
| **Пароли AD** | вошедший | Операционный отчёт (не настройки SMTP) |
| **Настройки** | вошедший | Конфигурация и рабочие списки. Сайдбар разбит на блоки по важности |

Справа: колокольчик уведомлений → имя → «Выйти».

**Убрано из topbar** (перенесено в Настройки): Действия, Учётные записи, Скрипты.

**Правило активного пункта:** dashboard модуля (`password_expiry.dashboard`) подсвечивает пункт модуля; страница `settings_page` того же модуля — пункт **Настройки**.

### 2.2. Подменю «Настройки»

Layout: `layouts/settings.html` — на ПК навигация в левом сайдбаре шириной 220 px. При ≤900px ссылка занимает половину ряда. При ≤480px — всю ширину.

Сайдбар — пять групп (разделитель между группами). Порядок — по важности. Экран входа живёт в **Общие**. Bind DN — в **Отчёт о паролях**. Пункт «Пароли AD» в topbar — операционный отчёт, не настройки.

| Группа | Раздел | Содержимое |
| --- | --- | --- |
| Платформа | Общие | PsExec, учёт WMI, сервисы экрана входа |
| Платформа | HTTPS | PEM, тумблеры TLS / Secure cookie |
| Платформа | Обновления | Self-update, sudo и службы. Ветки кода видны у копии |
| Сеть | Сектора | CIDR. Доступ по людям и группам не настраивается |
| Сеть | Опрос сети | Расписание опроса, bAD, журнал прогонов. Учёт WMI не здесь |
| Почта и AD | Почта (SMTP) | Общий SMTP для отчётов. Пустые поля — `SMTP_*` из `.env` |
| Почта и AD | Отчёт о паролях | Bind DN, пороги, search_base, cron, получатели, IMAP (тумблеры schedule — на dashboard) |
| Автоматизация | Скрипты | Библиотека `/admin/scripts`. Пачки — ссылка на странице, не в сайдбаре |
| Операции | Действия и аудит | Лента событий и журнал аудита. Справочник «Типы действий» не показывается |
| Операции | Обнаруженные УЗ | УЗ на конечных точках |
| Операции | Удаление дублей | Дубли по SN, призраки без SN, история IP, слабые совпадения |

Блок «Состояние планировщика» убран: последний прогон уже есть в журнале «Опрос сети», а из панели нельзя было ничего сделать.

### 2.3. Карточка устройства

Набор вкладок зависит от типа устройства. **«Прочее»** считается как ноутбук
(ещё не классифицированное имя) — те же вкладки УЗ / команды / оборудование.

| Вкладка | Ноутбук / СБ / Прочее | Сервер | Периферия (камера, МФУ, MikroTik, …) |
| --- | --- | --- | --- |
| Обзор | да (+ MAC/адреса, УЗ, краткое железо; SN — только у ноут/СБ; MAC не дублировать с таблицей адресов) | да (+ краткое железо, без MAC/УЗ/SN) | да; MAC — если опрашивается; без SN/УЗ/железа |
| История | да | да | — |
| Скрипты | да | да | — |
| Оборудование | да | да | — |

На **обзоре** один заголовок, один бейдж статуса, IP / серийный номер / MAC с копированием. Под бейджем — колонка статуса. Паспортные поля — в блоке с заголовком, как у сетевых адресов. Железо — одна строка под портретом в левой колонке и ссылка на вкладку, без второй таблицы процессора и дисков. Если устройство офлайн, в колонке статуса — «Проверить сейчас» и живой лог. Ping и Tracert на карточке нет. Пока проверка, опрос железа или опрос сети идёт, под кнопкой список реальных шагов в рамке: видны последние строки, остальные — прокруткой. После окончания список остаётся на обновлённой вкладке. Если устройство онлайн, в колонке статуса — CMD, PowerShell и ссылка **Скрипты** на вкладку `commands`. Оператор выбирает учётку в одном модальном окне. Подтверждение CMD или PowerShell открывает scripts/run в том же окне; строка ввода готова. Вкладка **Скрипты** показывает плитки и «Добавить скрипт». Плитка запускается через то же модальное окно учётки. Пачки этой машины — вкладка **История** и `/admin/scripts/batches`. Блока «Рабочий стол в браузере» нет.

Все пункты меню настроек открываются под `/admin/…`. Отчёт «Пароли AD» в верхней строке остаётся `/password-expiry` и не дублирует страницу порогов.

Контекст действия живёт **рядом с объектом**, а не дублируется в глобальном меню.  
Серийный номер на карточке/карте — **только** ноутбуки и СБ.  
MAC: ноутбуки / СБ / прочее всегда; камера / МФУ / MikroTik — только если уже опросили.

| Роль | Класс / правило | Размер |

## 4. Компоненты

### 4.1. Shell

- `.app-shell` → sticky `.app-topbar` → `.app-topbar-inner`, `.app-main` и `.app-main-wide` делят `--page-width` (1400px)
- Favicon: `static/favicon.ico` + `favicon.svg` (подключены в `base.html`)
- Карта, настройки, отчёты, списки с таблицами — **wide**
- Login, ошибки — узкий main / login-layout

### 4.2. Page header

```html
<div class="page-header">
  <div>
    <h1 class="page-title">…</h1>
    <p class="page-subtitle">одна короткая фраза</p>
  </div>
  <!-- опционально: 1 primary CTA -->
</div>
```

Справа — максимум одна primary-кнопка + вторичные outline. Не свалка форм.

### 4.3. Panel / content-card

- Обёртка данных: `.panel` + при необходимости `.content-card`
- Таблицы внутри панели: `p-0 overflow-hidden` + padding только у шапки
- Не оборачивать каждую метрику в «карточку ради карточки», если это не KPI-ряд отчёта

### 4.4. Кнопки

| Вариант | Когда |
| --- | --- |
| `btn-primary` | Главное действие экрана / формы (сохранить, запустить) |
| `btn-outline-primary` | Вторичное связанное (dry-run, экспорт) |
| `btn-ghost` / `btn-outline-secondary` | Нейтральное (выйти, сброс, назад) |
| `btn-warning` | Опасная/мощная операция (произвольная remote command) |
| `btn-sm` | Toolbar, inline, сайдбар устройства |

На одной визуальной группе — **один** primary.  
Полная ширина (`w-100`) — только в узком сайдбаре действий устройства.

### 4.5. Формы

- Label всегда виден (или `visually-hidden` с aria)
- Focus ring: soft (`rgba(171, 203, 88, 0.12)`)
- Пароли: placeholder «задан / не задан», пустое поле = не менять
- CSRF hidden на каждом POST
- Live-search: `data-live-*` + hint «начните вводить…»

### 4.6. Таблицы

- `table table-sm` для плотных журналов
- Числа — `text-end` + tabular nums где уместно
- Пустое состояние: одна строка `colspan` + `text-muted`
- Пагинация: макрос `page_nav` + `.app-pagination`

### 4.7. Статусы

| Статус | Цвет | UI |
| --- | --- | --- |
| online | `--ok` | левая кромка + badge + `.status-dot` |
| offline | `--bad` | то же |
| unknown | `#6c757d` | то же |
| success / failed / running (runs) | ok / bad / accent-ink | `.batch-run-status[data-status]` |

Не полагаться только на цвет: текст badge обязателен.

### 4.8. Entity links

- Устройство: `.entity-link.entity-device`
- УЗ: `.entity-link.entity-account`
- Макросы в `macros/status.html` — предпочитать их ручной разметке

### 4.9. Уведомления

Колокольчик в topbar; панель ≤22rem; unread — soft accent fill.  
Не дублировать ленту уведомлений отдельным пунктом меню.

### 4.10. Terminal / run log

Тёмный блок `.terminal-panel` — исключение из светлой темы (инструмент оператора).  
Не растягивать dark theme на весь продукт.

### 4.11. Report service toggle

Общий паттерн для «Пароли AD»:

- `.report-service-toggle` (+ `.is-on`)
- Тумблер schedule + статус службы `bawh-password-reports`
- Primary «Запустить сейчас» + outline «Тестовый прогон»
- Экспорт CSV отчёта о паролях — outline-primary

Конфигурация cron — **только** в Настройках модуля; SMTP — в **Настройки → Почта (SMTP)**. Не на dashboard (кроме паузы рассылки пользователям — операционное).

## 5. Экраны и паттерны layout

### 5.1. Карта сети

1. Header + автообновление  
2. Сводка метрик (не KPI-карточки)  
3. При ≥900 px левый **sticky**-сайдбар 300 px держит поиск и фильтры; иначе одна колонка, поиск **sticky** под topbar.  
4. Секторы → сетка устройств  
5. Sticky bulk-bar при выборе  

Поиск: hostname, IP, MAC, SN **или пользователь (УЗ)**.  
На карточке ноутбука/СБ — текущий пользователь, если известен.  
Имена `BN***` (префикс `bn` + 3 или 5 цифр) — ноутбуки.

Layouts: `list` | `cards` | `tiles` — preference в localStorage.  
На ≤640px сетка = 1 колонка.

### 5.2. Списки (Действия и аудит, Обнаруженные УЗ)

Вход — **Настройки**, не topbar.  
Header → (опционально справочник) → таблица.  
Журналы действий / аудита / истории УЗ: по умолчанию последние **5** + «Показать все» (как на карточке устройства и в опросах).  
В режиме «Показать все» у ленты действий — live-search и пагинация.  
Обнаружения УЗ в ленте **группируются** (одно событие на пару УЗ+устройство, счётчик повторов).

### 5.3. Настройки

Длинные admin-формы — **отдельные разделы** сайдбара, внутри — секции-панели с одним submit.  
Журналы опросов (сеть / железо): по умолчанию последние **5** строк + ссылка «Показать все» с пагинацией.

### 5.4. Login

`.login-layout`: форма + статус сервисов. На ≤800px — колонка.  
Минимум декора; фокус на входе.

## 6. Адаптивность

| Breakpoint | Поведение |
| --- | --- |
| ≥992px | Topbar: nav + user в одну линию; toggler скрыт |
| ≤991px | Topbar: SVG-гамбургер + колокольчик/выход снаружи collapse; пункты меню столбиком на всю ширину; карта — сайдбар поиска/фильтров сверху, результаты снизу |
| ≤900px | Settings nav: каждая ссылка — половина ряда (сетка 2×N, без горизонтального скролла) |
| ≤480px | Settings nav — одна колонка на всю ширину |
| ≤960px | Device object: портрет сверху; actions sidebar сверху |
| ≤800px | Login: одна колонка; page-header / refresh карты — столбиком |
| ≤720px | Map list-layout → column; search form column |
| ≤700px | Bulk-bar actions на всю ширину; meta-list / pagination / terminal wrap |
| ≤640px | Device cards — 1 колонка; портрет на всю ширину; плотнее padding main |

**RDP / mid-band (≈760×1417):** типичный кейс Windows App на iPhone → Chrome на удалённом ПК. Collapse включается (&lt;992), поэтому иконка меню обязана быть собственной SVG — **не** полагаться на `.navbar-toggler-icon` без родителя `.navbar` (CSS-переменная фона пустая → пустая кнопка). Подменю «Настройки» — **две колонки** ссылок, не одна строка со скроллом; таблицы — только внутри `.table-responsive`; у grid/settings-content — `min-width: 0`.

**Touch:** hit-area кнопок выбора/избранного ≥1.7rem; toggler/колокольчик 2.15×2.15rem; bulk-bar не перекрывает контент без отступа (`bottom: 0.85rem`).  
**Viewport:** meta `width=device-width, initial-scale=1` обязателен.  
**Не** фиксировать ширины таблиц жёстко — `.table-responsive`.
**Overflow:** на `.app-shell` — `overflow-x: hidden` (не `clip`: иначе ломается горизонтальный scroll у `.table-responsive`).  
**RDP / mid-band:** без `background-attachment: fixed` и без `backdrop-filter` на topbar ≤991px; collapse без height-transition.

## 7. Доступность и обратная связь

- Навигация: `aria-label`, `aria-expanded` на toggler и колокольчике  
- Live-регионы: сводка карты, hint проверки устройства (`aria-live="polite"`)  
- Flash: Bootstrap alert + `.app-flash` (success / danger / warning / info)  
- Disabled: opacity + `cursor: not-allowed` (run controls)  
- Фокус не снимать кастомными `outline: none` без замены  
- Иконки без текста — только с `aria-label` / `aria-hidden` + соседний текст

## 8. Движение

Допустимо:

- Hover карточки: `translateY(-1px)` + лёгкая тень (120ms)  
- Chevron сектора: rotate 150ms  
- Подсветка найденной карточки: `map-card-return` ~2.4s  
- Progress bar batch: width 250ms  

Запрещено: бесконечные pulse/glow, parallax, тяжёлые page transitions.

## 9. Копирайт и тон

- Русский язык UI (как сейчас)  
- Короткие глаголы: «Сохранить», «Запустить», «Проверить сейчас»  
- Subtitle — что делает экран, не маркетинг  
- CLI-подсказки — `small text-muted`, не в hero  
- Ошибки — человеческим языком + technical detail secondary

## 10. Разделение «работа» vs «конфиг»

| Операция | Где |
| --- | --- |
| Смотреть статусы, искать, bulk ping/script | Карта |
| Смотреть отчёт паролей, ручной прогон, пауза писем | Dashboard модуля (topbar) |
| SMTP | Настройки → Почта (SMTP) |
| Bind DN модуля паролей | Настройки → Отчёт о паролях |
| Пороги и получатели паролей | Настройки → Отчёт о паролях |
| Расписание опроса, bAD, журнал прогонов | Настройки → Опрос сети |
| Опрос одной машины с карточки | Карточка → вкладка «Оборудование» |
| Вкл/выкл расписания отчёта | Dashboard модуля (тумблер) |
| PsExec, учёт WMI, экран входа | Настройки → Общие |
| sudo и службы | Настройки → Обновления |
| Self-update | Настройки → Обновления |
| HTTPS / PEM | Настройки → HTTPS |
| Поиск и удаление дублей устройств | Настройки → Удаление дублей |
| Запуск команды на одном ПК | Карточка → обзор: CMD или PowerShell и модальное окно учётки; подтверждение открывает scripts/run. Плитка — вкладка «Скрипты», то же окно учётки |
| Ping / Tracert | Маршруты POST есть; на карточке устройства входа нет |
| Библиотека скриптов | Настройки → Скрипты |
| Лента действий / аудит | Настройки → Действия и аудит |
| Обнаруженные УЗ на ПК | Настройки → Обнаруженные УЗ |

**Запрет дублей:** одна capability — один канонический вход. Второй вход допустим только как deep-link («Настройки модуля» с dashboard) или object-scoped action (кнопка на карточке).

## 11. Кто видит интерфейс

Вошедший видит все разделы и может выполнять все действия на экране.
Кто не в группе `LDAP_ADMIN_GROUP`, на сайт не попадает (если группа задана).
Анонимный запрос останавливает сервер, даже если ссылка известна.

## 12. Чеклист нового экрана

1. Расширяет существующий layout (`base` / `layouts/settings`) — не invent shell  
2. Токены из `:root`, без новых «случайных» hex (кроме обоснованных entity/status)  
3. Один `page-title`, один primary CTA  
4. Работает ≤640px без горизонтального скролла страницы (таблицы — в `.table-responsive`)  
5. Не дублирует действие, уже доступное в другом подменю  
6. `@login_required` на маршруте совпадает с видимостью кнопок  
7. Пустые и ошибочные состояния оформлены  
8. Документирован в ARCHITECTURE §Frontend при новом JS-модуле

## 14. Выравнивание UI (v1.5 → v1.6)

Закрыто при внедрении гайдбука:
