# План развития bAWH → полноценный веб-помощник админа

Документ для команды из 5 человек: куда движемся, какие фичи даём, кто за что отвечает.
Опирается на текущий стек (Flask SSR + сервисы + PostgreSQL + LDAP + PsExec + планировщик) и принцип **не ломать совместимость**.

Связанные материалы: [README.md](../README.md), [ARCHITECTURE.md](ARCHITECTURE.md). Текущая версия на момент плана: **0.2.x**.

---

## 1. Цель продукта

bAWH уже умеет: карта сети, опрос/WMI, УЗ на ПК, диагностика, скрипты через PsExec, пароли AD, ACL по секторам.

**Цель улучшений** — сделать из него ежедневный операторский инструмент админа:

1. Быстро понять состояние сети и «что горит».
2. Найти устройство / УЗ / событие за секунды.
3. Сделать типичное действие (пинг, скрипт, команда) в 1–2 клика.
4. Получить сигнал об инциденте без постоянного обновления страницы.
5. Сохранить текущие URL, роли admin/user и серверный рендер как основной UI.

Не цель первой волны: публичный SaaS, мобильное приложение, полный REST для внешних систем, Linux remote runtime (UI уже намекает — отдельно и позже).

## 2. Направления разработки (куда улучшаемся)

Пять направлений. Каждое близко к текущему функционалу и даёт новые фичи + UX без ломки API/маршрутов.

### A. Операторский контур (IA + UX)

**Проблема сейчас:** в верхнем меню только «Карта» / «Пароли AD» / «Настройки». Скрипты, УЗ, действия, секторы спрятаны под «Настройки» — операторский путь размыт.

**Куда идём:**

- Пересобрать навигацию: операторские разделы (Карта, Действия, УЗ, Скрипты) отдельно от админских (Секторы, Параметры, Обновления, Сервисы входа, Пароли AD → настройки).
- Дашборд сети рядом с картой: последний опрос, % online/offline, failed script runs, краткая сводка паролей AD (для admin).
- Deep-link фильтры карты в URL (`?status=offline&type=W&q=...`), чтобы F5 и шаринг ссылки работали.
- Избранные устройства и «недавние» (localStorage сначала, опционально таблица позже).
- Автоcomplete поиска на карте через уже существующий `GET /search/suggest`.

**Совместимость:** старые URL остаются; «Настройки» можно оставить как вход в settings-layout.

### B. Быстрые операции на устройствах

**Проблема сейчас:** с карточки устройства пинг/команда уводят на `/scripts/runs/<id>`; запуск скрипта — через отдельную длинную форму; multi-select на карте нет.

**Куда идём:**

- «Запустить скрипт» прямо с вкладки commands карточки устройства (тот же `start_script_on_devices`).
- Пресеты команд (`whoami`, `ipconfig /all`, `hostname`, `netstat -ano`) на вкладке commands.
- Multi-select на карте → bulk ping / bulk script (batch_id уже есть в `script_runs`).
- Страница очереди batch-запуска: прогресс N/M, failed hosts, повтор failed.
- Inline-превью результата ping/tracert на карточке (polling того же `/scripts/runs/<id>/status`), полная страница run — по ссылке.

**Совместимость:** существующие маршруты diagnostics/scripts не удаляем; добавляем точки входа и UI.

### C. Сигналы и наблюдаемость

**Проблема сейчас:** уведомления есть только у паролей AD (SMTP). Сеть «молчаливая»: офлайн важных хостов и failed poll/WMI не сигналят.

**Куда идём:**

- In-app лента уведомлений поверх `action_service` + новых событий (failed poll, WMI error, script failed).
- Watchlist устройств: «сообщить, если offline N минут».
- Health-блок в админке: статус `bawh-scheduler`, время последнего `network_poll_runs`, счётчик ошибок WMI за прогон.
- Опционально webhook/SMTP для критичных сетевых событий (по образцу password mailer).
- Карта: подхватывать **новые** устройства mid-session (сейчас `/map/status` обновляет только уже отрисованные карточки).

**Совместимость:** password expiry не трогаем; новые каналы — отдельные настройки.

### D. Права и аудит (Authz v2)

**Проблема сейчас:** бинарно admin / user. Non-admin видит сектора по ACL, может ping/tracert, но не скрипты. Нет журнала «кто изменил сектор/настройки».

**Куда идём:**

- Роли поверх LDAP-групп без ломки `sector_access`:
  - `viewer` — только чтение карты/устройств/истории;
  - `operator` — ping/tracert + запуск разрешённых скриптов на своих секторах;
  - `password_viewer` — отчёт паролей AD без настроек SMTP;
  - `admin` — как сейчас.
- Audit-таблица админ-действий (sector CRUD, settings, script create/edit, update/rollback).
- В селектах скриптов — только устройства/секторы, видимые пользователю (сейчас в форму попадают все).
- Фильтры и пагинация в `/actions`, `/accounts`, истории опросов.

**Совместимость:** текущий `is_admin` и `sector_access` остаются источником прав; новые роли — additive флаги/группы из `.env` / LDAP.

### E. Платформа и качество

**Проблема сейчас:** ad-hoc JSON, CDN шрифтов/Bootstrap (риск для закрытой сети), нет пагинации/экспорта, история устройств без партиций.

**Куда идём:**

- Стабилизировать JSON-эндпоинты как внутренний API v1 (`/api/v1/...`) с session+CSRF как сейчас; старые пути оставить aliases/redirect.
- Self-host Bootstrap + шрифты (или system fallback) для air-gapped.
- Пагинация / cursor + CSV-экспорт УЗ, истории опросов, actions.
- Усилить тесты: authz ролей, batch UI-логика сервисов, регрессии карты/search.
- Документировать операторские сценарии в `docs/` (runbooks).
- Linux/bash remote — **отдельный этап после** Windows-операторского контура.

**Совместимость:** semver в `VERSION`; миграции только additive; deprecated URL живут минимум один минорный релиз.

## 4. Команда из 5: роли

Все мультизадачные (код + тест + лёгкий дизайн UI в рамках текущего `app.css`). Ниже — **основная зона ответственности** и **обязательные пересечения**, чтобы не было «чужих» дыр.

Имена ролей условные — назначайте людей, не меняя зоны.

### P1 — Tech Lead / Архитектор продукта

**Зона:** целостность продукта, совместимость, релизный ритм, спорные решения.

**Делает:**

- Ведёт этот roadmap: что входит в волну, что откладывается.
- Согласует контракты маршрутов/API и миграций (additive only).
- Code review всех PR по authz, credentials, update_service, ping_service.
- Следит за semver (`VERSION`) и changelog для страницы обновлений.
- Пишет/обновляет `docs/ARCHITECTURE.md` при структурных изменениях.
- Разруливает конфликты «быстрее UI» vs «не ломать SSR/authz».

**Тестирует:** смоук после деплоя (`/health`, логин LDAP, карта, ручной poll), регрессии опасных путей (PsExec, Fernet, update/rollback).

**Дизайн:** утверждает IA навигации (какие пункты в topbar vs settings).

**Не делает в одиночку:** всю вёрстку волны; весь feature-код устройств.

**Definition of Done волны (владелец):** все 5 ролей отметили свои DoD; README актуален; нет breaking changes без миграционного пути.

---

### P2 — Frontend / UX (шаблоны + static)

**Зона:** `app/templates/`, `app/static/css`, `app/static/js`, ощущение «помощника» в браузере.

**Делает (W1–W2):**

- Новая навигация в `base.html` + подменю settings-layout.
- Виджеты сводки на карте/дашборде (online/offline, последний poll).
- Deep-link фильтры + избранное (localStorage) в `map.js` / `search.js`.
- Подключение `/search/suggest` к полю поиска карты.
- UI «запуск скрипта с карточки», пресеты команд, multi-select + bulk bar.
- Страница прогресса batch; улучшение `run_log.js` при необходимости.
- Адаптив mobile/desktop в духе текущего Manrope/teal (без смены визуального языка).

**Тестирует:** ручной UX-прогон Chrome/Firefox; проверка без JS-ошибок в консоли; пустые состояния (нет устройств, нет прав).

**Дизайн:** wireframe в комментарии PR или простой HTML-прототип в существующем CSS; не вводит новую дизайн-систему.

**Пересечения:** контракты JSON согласовывает с P3; права скрытия кнопок — с P4.

**Definition of Done:** страница читается без инструкций; F5 сохраняет фильтры карты; опасные кнопки не торчат у user без прав.

---

### P3 — Backend сети и операций

**Зона:** устройства, опрос, поиск, скрипты/PsExec, batch, health опроса.

**Делает:**

- Эндпоинты/сервисы для дашборд-сводки (агрегаты из `devices`, `network_poll_runs`, failed `script_runs`).
- Быстрый старт скрипта на одном device_id (тонкая обёртка над `script_service`).
- Bulk-операции и статус batch (сводка по `batch_id`).
- Расширение `/map/status` (или соседний endpoint) для новых устройств + агрегатов.
- Health scheduler: «жив ли процесс / когда последний успешный poll» (чтение журнала + опциональный heartbeat-файл/setting).
- Пресеты команд как данные (seed или константа), не хардкод только в HTML.
- Рефакторинг селектов скриптов на `get_visible_*`.

**Тестирует:** pytest на сервисы (`test_script_service`, `test_ping_service`, `test_search_service` + новые); сценарии offline host / empty sector.

**Пересечения:** UI — P2; права на bulk/script для non-admin — P4; релиз/миграции — P1.

**Не ломает:** `run_network_poll`, WMI-учётку в главном потоке, контракт `script_runs` polling.

**Definition of Done:** новые фичи покрыты тестами; ручной poll и scheduler не конфликтуют; batch не зависает без cancel-пути.

---

### P4 — Authz, идентичность, аудит, пароли AD

**Зона:** `authz.py`, LDAP-группы, credentials, password expiry, audit, роли.

**Делает:**

- Authz v2: маппинг LDAP-групп → флаги ролей (additive к `is_admin`).
- Разрешить `operator` запускать **опубликованные** скрипты на доступных секторах (CRUD скриптов — по-прежнему admin).
- `password_viewer` для дашборда паролей без settings.
- Таблица `admin_audit_log` + запись из sector/admin/scripts/update критичных POST.
- Жёсткая проверка authz в селектах и bulk (не только в момент execute).
- Пагинация/фильтры `/actions` и `/accounts` с теми же правилами видимости.

**Тестирует:** матрица прав (admin / operator / viewer / user с sector_access / без доступа) в `test_authz.py` и route-тестах.

**Дизайн/UX:** тексты 403 и подсказки «нет прав на запуск» — понятные, без утечки существования чужих устройств (как сейчас 404-паттерн).

**Пересечения:** P1 review обязателен; P3 — точки enforce в script/bulk; P5 — фикстуры ролей.

**Definition of Done:** нельзя обойти UI прямым POST; старые админы из `LDAP_ADMIN_GROUP` ведут себя как раньше; audit пишет actor + action + entity id.

---

### P5 — QA, платформа, деплой, документация

**Зона:** тесты, CI-дисциплина, deploy/air-gap, runbooks, регрессии волн.

**Делает:**

- Чеклисты ручного регресса на каждую волну (логин, карта, device tabs, scripts run/cancel, admin poll, password expiry, updates).
- Расширяет pytest там, где P2–P4 не покрыли edge cases; стабилизирует flaky.
- Self-host / vendor Bootstrap+fonts **или** документированный offline-режим.
- Проверяет `deploy/install-debian12.sh` и systemd-юниты после изменений scheduler/heartbeat.
- Пишет `docs/runbooks/` : «устройство offline», «WMI не отвечает», «PsExec отказал», «пароли AD не уходят».
- Следит за `.env.example` при новых переменных ролей/webhook.
- Лёгкий perf-взгляд: карта на большом секторе, polling run_log не долбит БД лишним.

**Тестирует:** это основная роль — принимает волну перед merge в `main` с точки зрения «можно отдавать админам».

**Дизайн:** проверяет a11y-минимум (фокус, aria у toggle меню, контраст статусов online/offline).

**Пересечения:** блочит релиз, если DoD P1–P4 не выполнены; эскалирует P1.

**Definition of Done:** чеклист волны пройден на стенде; новые env задокументированы; нет регресса install-скрипта.

## 7. Правила совместной работы

1. **Ветки:** `feature/<id>-short-name` от актуального `main`; один ID из таблицы волны.
2. **Слои:** маршрут не пингует и не ходит в LDAP — только через `services/` (как в ARCHITECTURE).
3. **Миграции:** только новые ревизии Alembic; уже применённые не редактировать.
4. **Секреты:** никаких паролей в git; новые ключи — в `.env.example` без значений.
5. **UI:** развиваем текущий visual language (Manrope, teal accent, Bootstrap 5), не устраиваем редизайн «с нуля».
6. **Права:** любой новый POST проходит через `authz`; UI-скрытие не считается защитой.
7. **Тесты:** новая ветка сервиса/authz —pytest обязателен; чистый CSS — ручной чеклист P5.
8. **Демо:** в конце волны — 15 минут на стенде: сценарий «нашёл ПК → запустил действие → увидел результат/сигнал».

## 8. Метрики успеха (как понять, что стали «помощником»)

| Метрика | Как смотрим |
| --- | --- |
| Время до первого действия | От логина до ping/скрипта на нужном ПК (цель — заметно короче за счёт карты/пресетов/карточки) |
| Доля операций без «Настроек» | Скрипты/УЗ/действия доступны из операторского меню |
| Прозрачность сети | На экране видны last poll + online% без захода в admin |
| Безопасный делегированный доступ | Operator работает на своих секторах без полного admin |
| Регрессии | Ноль критичных после волны на чеклисте P5 |

## 9. Что сознательно не берём в ближайшие волны

- Публикация сервиса в интернет / OAuth для внешних IdP сверх текущего LDAP.
- Полноценный SPA-rewrite (React/Vue) — усиливаем SSR + точечный JS.
- Замена PsExec на WinRM/SSH как единственный канал (можно spike, не замена).
- Мобильное нативное приложение.
- Автоматический remediation («сам перезагрузит службу») без явного подтверждения оператора.

## 10. Быстрый старт для команды

1. P1 назначает людей на роли P2–P5 и нарезает W1-01…W1-10 в трекер.
2. Вместе проходят 30 минут по продукту на стенде: карта → устройство → скрипт → admin poll → пароли AD.
